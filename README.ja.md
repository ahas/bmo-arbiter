# bmo-arbiter

複数のサービスがグラフィックカードを共有する GPU ノードクラスタのためのカードアービターです。二つのプログラムから
なります。

- **ノードアービター**は各 GPU ノードに一つずつ動くプロセスで、そのノードのカードロックを管理します。誰がどの順番で
  カードを使えるか、すべての占有者がチケットとして順番を待つキュー、カードを即座に取得するクレーマント、使用中に
  カードを占有する人のデスクトップ、そしてエンジンのメモリのうちホストメモリやダンプストアに退避して再びロードする
  単位を扱います。自分のカードを別ノードのエンジンに貸し出すこともできます。
- **マスター** `bmo-arbiter` はクラスタに一つだけのプロセスで、どのサービスをどのノードに置くかを決め、ノード
  アービターをインストールし、配置ルールに従ってすべてのカードのメモリを計画し、クラスタ全体とその配置を提供します。

アービターはどのサービスも名前では知りません。各サービスが自らを宣言し、ノードアービターに名乗り、マスターの
アダプター動詞に応答します。アービターは上流のユニットです。ハーネスは他のユニットが一つも動いていなくても、MCP
サーバー `bmo-arbiter mcp` を通じてカード上の順番を取得できます。スーパーバイザーは、ツールホストからマスターの使用量
ルートを呼び出すホスト型ツール `bmo/gpu` で、すべてのカードが何をしているかを読み取ります。

## 構成

| フォルダ | 内容 |
|---|---|
| `src/` | マスターのパッケージ：ライブラリと `bmo-arbiter` バイナリ |
| `crates/` | アービターが公開するクレート：すべてのボディとすべてのルートの呼び出しを持つ `client/`、そして MCP サーバー、`bmo-arbiter` スキル、OpenAPI ドキュメントの生成器を持つ `plugin/` |
| `packages/` | `docs/openapi.json` から生成される TypeScript クライアント `arbiter-client/` |
| `card/` | ノードアービター：Python パッケージ、固定された `pyproject.toml`、ノードのセットアップとユーザーユニット。そのまま各ノードにアップロードされる |
| `tests/` | リポジトリのチェックとすべてのテスト：マスターのテストは Cargo テストとして、ノードアービターの Python テストは `tests/card/` 配下に |
| `tools/` | アービター自身のホスト型ツール：スーパーバイザーがすべてのカードを読む `gpu/`。デプロイ時に配置・登録される |
| `docs/` | アービターが何をするかの正規の記述と OpenAPI ドキュメント |
| `deploy/` | デプロイがデプロイツリーからリンクする、マスターの systemd ユーザーユニット |

ルートには Cargo マニフェスト、バージョン、MIT ライセンス、韓国語台帳を伴う `testbed.toml`、`install.toml`（新しいマシンにユニットをインストールするのに必要なもの）、`rustfmt.toml`、
`CLAUDE.md` があります。

## ドキュメント

| ドキュメント | 内容 |
|---|---|
| `docs/api.md` | 境界：両プログラムのすべてのルート、クライアントとハーネスプラグイン、アービターが公開または呼び出すすべてのプロトコル、ファイル、動詞、設定、コード、バージョンのルール、そして共有プール上で受け入れがどこで決まるか |
| `docs/openapi.json` | 同じルートを OpenAPI 3.1 の契約として表したもの。クライアントの型から生成 |
| `docs/node-arbiter.md` | ノードアービター：ロック、占有者、クレーマント、デスクトップ、キーパー、ホールド、貸し出し、インストール |
| `docs/placement.md` | 単位、ホストメモリ、ダンプストア、マスターとスレーブ、サービスの配置、ルール |
| `docs/PERSONAL-DATA.md` | リポジトリに個人データを置かないルールと、追跡されるすべてのファイルにそれを適用するチェック |

## バージョン

- **リポジトリ全体で一つのバージョン、** 最初のリリースまではリビジョン付きの `0.1.0` です。`VERSION` がそれを
  保持し、すべてのクレートと TypeScript パッケージが同じバージョンを持ち、ノードアービターも同じバージョンを自身の
  バージョンとして表示します。
- **変更がバージョンをどう動かすか**は `docs/api.md` の「Versions」に記載されています。

## コマンド

```sh
cargo check --workspace --all-targets
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test
cargo run -p bmo-arbiter-plugin --example openapi > docs/openapi.json
bun run --cwd packages/arbiter-client generate
bun run --cwd packages/arbiter-client check
```
